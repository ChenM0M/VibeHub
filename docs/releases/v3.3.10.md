# VibeHub 3.3.10

## 用户可见变化

- 修复 v3.3.7 引入的 Windows 迁移回归的最后一处:项目事件锁释放后,Windows 上的 delete-pending 窗口会让其他线程的锁创建收到 `Access is denied` 而非「已存在」,被误判为致命错误。现在这类拒绝被识别为锁交接中的正常竞争并在超时窗口内重试。
- 与 v3.3.8(重命名前关闭句柄)、v3.3.9(备份刷盘使用写句柄)共同构成完整的 Windows 修复系列;三处均为 fail closed,不涉及用户数据变更。
- macOS 与 Linux 行为不变。

## 验证边界

本版本已通过 `release:check`、前端构建、V3 contracts、Rust workspace 测试(`--locked`)、CLI 构建、MCP contract test 与 macOS bundle strict codesign 检查;预期 Windows CI 的存储/MCP 测试在本版本全部转绿。

Windows 原生验收(文件锁、原子替换、崩溃恢复、路径语义,以及同一 Release artifact/hash 的 A07、E07、F07–F10、G05 手测)仍需在发布后使用本版本 Windows artifact 在 Windows 10/11 主机或可信 VM 完成;macOS/CI 证据不替代该手测。已知交接项:若干既有模块(agent profiles、project settings 等)存在只读句柄 `sync_all` 模式,纳入发布后 Windows 验收清单,不在本补丁范围。
