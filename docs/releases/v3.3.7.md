# VibeHub 3.3.7

## 用户可见变化

- V3 事件存储升级到 store format 2：在保留 `events.jsonl` 作为不变审计事实源的同时，新增一个可从零重建的 SQLite（WAL）增量索引 `store-v2.sqlite3`。旧项目首次访问时自动完成一次性兼容迁移——先写带 SHA-256 清单的内容寻址备份，再用全量重放逐字段校验新索引，全部通过才原子替换；任何失败都会 fail closed 并保留源数据，可安全重试。
- 日常的任务读写不再整本重放事件日志：1k Tasks / 50k events 基准下 steady-state append p95 约 20.5 ms，真实项目规模（约 6k events）task-view 连续 20 次 p95 约 249 ms；事件规模增长不再导致写入回到全量重放路径。
- 归档任务改为分页查询（`task_archive_page`），project-overview 视图新增 `archived_task_count` 与分页查询契约，Cockpit 归档列表按页加载，大型项目不再一次性物化全部归档任务。
- 并发写入、幂等、partial-tail 隔离、索引落后、迁移回滚与损坏恢复等路径由新增的存储测试与 contract test 覆盖；设计决策见 `docs/v3/adr/006-task-scoped-incremental-event-store.md`。

## 验证边界

本版本已通过 `release:check`、前端构建、V3 contracts、Rust workspace 测试（`--locked`）、CLI 构建、MCP contract test、`git diff --check` 与 macOS bundle strict codesign 检查。存储相关的并发、故障注入与迁移恢复测试在 macOS 原生通过（29 项）。

Windows 原生验收（文件锁、原子替换、崩溃恢复、路径语义，以及同一 Release artifact/hash 的 A07、E07、F07–F10、G05 手测）仍需在发布后使用本版本 Windows artifact 在 Windows 10/11 主机或可信 VM 完成；macOS/CI 证据不替代该手测。
