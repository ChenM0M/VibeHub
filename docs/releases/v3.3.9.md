# VibeHub 3.3.9

## 用户可见变化

- 完成v3.3.8 开始的 Windows 迁移回归修复:迁移备份在写入 `events.jsonl` / `projection.json` 副本后,原实现用只读句柄调用 `sync_all()` 刷盘;Windows 的 `FlushFileBuffers` 要求写权限句柄,因此 Windows 上首次 store format 1 → 2 迁移仍会以 `Access is denied (os error 5)` 失败。现改用写句柄刷盘。
- 与 v3.3.8 的重命名句柄修复合并后,store format 1 → 2 一次性迁移在 Windows CI 的全部存储与 MCP 测试中通过;macOS 与 Linux 行为不变。
- 迁移失败始终为 fail closed:源 `events.jsonl` 与用户数据不受影响,安装本版本后重试迁移即可。

## 验证边界

本版本已通过 `release:check`、前端构建、V3 contracts、Rust workspace 测试(`--locked`)、CLI 构建、MCP contract test 与 macOS bundle strict codesign 检查;Windows CI 测试在本版本应全部转绿。

Windows 原生验收(文件锁、原子替换、崩溃恢复、路径语义,以及同一 Release artifact/hash 的 A07、E07、F07–F10、G05 手测)仍需在发布后使用本版本 Windows artifact 在 Windows 10/11 主机或可信 VM 完成;macOS/CI 证据不替代该手测。已知交接项:若干既有模块(agent profiles、project settings 等)亦存在只读句柄 `sync_all` 模式,纳入发布后 Windows 验收清单,不在本补丁范围。
