# VibeHub 3.4.0

Agent 现在可以一次读取当前工作的目标、范围、约束、关联验收、关键阻塞和下一步，再按需查看详情与原始证据。新生成的宿主连接默认提供 12 个常用工具；已知实体 ID 可以直接查询，高级操作通过明确切换目录使用。

- 新增 `workspace_context`、`task_brief`、`task_inspect`，默认简报限制为 16 KiB。服务端过滤、分页和有界关联查询不再先构造完整桌面 bundle。
- 下一步明确区分工具调用、实际工作、证据、用户输入及外部等待。Schema 暴露合法参数，错误提供可执行的修正或刷新路径。
- `task_start`、`task_record`、`session_finish` 使用稳定 request_id 和可查询的恢复记录；context handle 仅在当前连接有效。绑定、版本、证据及当前用户完成确认继续严格校验。
- 桌面后台使用 revision 探测与面板缓存，未变化时不重复发布 bundle；诊断导出仅在显式请求时生成，可完整分块读取、校验 hash 和删除。
- 保留 legacy 接口、既有事件事实和权威配置。升级不会将 Session 收尾自动视为 Task 完成。需要回退接口时先查询未完成 operation，保留其恢复记录。
- 合并重复导出和操作日志写入逻辑，移除已被替代的宿主配置检查及未使用辅助函数，减少重复职责。

固定的 14 类交互样本中，工具结果字节相对 B0 减少 92.79%；此结果不是所有任务或模型的保证。Codex、Claude Code、OpenCode 已在记录的模型与版本上通过重复隔离闭环及重连验证。完整诊断和大证据展开仍需要额外调用。

macOS/Windows 源码原生验证已经执行；精确 Release 安装包的原生安装、IDE、升级/回滚和卸载验证单独记录，不由 CI 构建成功替代。签名状态以各产物实际信息为准；未配置正式签名凭据的平台采用 ad-hoc/unsigned 构建。

详细契约、测量范围和逐项证据见 [设计与验收记录](../../docs/v3/agent-native-mcp-redesign.md)。
