# VibeHub 3.3.11

## 用户可见变化

- 修复 Claude Code Agent Profile 的配置串线与漂移：Profile 激活改为仅更新激活索引，切换/激活/启动不再把一个 Profile 的 provider、凭据、主模型或高级模型覆盖到另一个 Profile 或共享用户配置。
- 修复 auto 模型语义：`__auto__`/空值保存后不再生成模型 override；只有明确选择的模型才写入对应 Claude Code 环境变量，未知模型保持可见。对齐 Claude Code 原生 settings 优先级与 `--settings`/`--setting-sources` 启动语义，子 Agent 与 Sonnet/Opus/Haiku 及小/快模型字段的契约、UI 文案与实际 env 映射一致；`CLAUDE_CODE_SUBAGENT_MODEL` 的强制覆盖语义在文档中明确记录。
- 修复 OpenCode provider 上游协议无法持久化保存的问题：协议选择此前被静默丢弃，读取路径一律推断为“未知”。现在协议会写入真实 `opencode.json` 的 npm 字段（Chat Completions → `@ai-sdk/openai-compatible`，Anthropic Messages → `@ai-sdk/anthropic`），读取时由 npm 包反向解析，歧义包保持“未知”而不猜测；`openai_responses` 会被明确拒绝而非静默丢弃。
- 新增 Profile 往返、隔离、安全与真实 CLI mock 冒烟测试覆盖（adapter 与命令边界）。

## 验证边界

本版本已通过 `release:check`、前端构建、V3 contracts、Rust workspace 测试（`--locked`）、CLI 构建、MCP contract test 与 macOS bundle strict codesign 检查。

Windows 原生验收（A07、E07、F07–F10、G05）仍需在发布后使用本版本 Windows artifact 与 `SHA256SUMS-windows-x64.txt` 在 Windows 10/11 主机或可信 VM 完成，不得以 macOS/CI 证据替代；Claude Code 原生启动语义在真实环境的复核同样待补。
