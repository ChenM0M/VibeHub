# RFC Backlog 001: V3 Domain and Event Contract

- Status: M0 boundary decided; M2 implementation decisions remain backlog
- Owner: V3 Core / Domain Contract owner
- Decision milestone: M0
- Implementation milestone: M2
- Related task: `T-20260711080143-b1ff21ea`
- Evidence: `.vibehub/research/current/research-pack.md` F001, F002, F005

## Problem

V2 has a useful append-only event log and fold-based projection, but its envelope and event vocabulary encode the capability workflow. V3 needs a domain contract for Project, Task, PlanNode, Session, Criterion, Finding, Attempt, confirmation, and projection freshness without leaking V2 YAML or UI component shapes.

## Invariants

1. The event stream is authoritative for V3 task state; derived views are disposable and rebuildable.
2. Append is atomic, idempotent, ordered per aggregate, and safe across desktop, CLI, and MCP processes.
3. Unknown future events are preserved and surfaced, never silently discarded.
4. Evidence grade and source references remain explicit.
5. JSON wire contracts are versioned independently from Rust/TypeScript implementation types.

## Decisions To Resolve

### D1. Contract source of truth

- A: JSON Schema 2020-12 first, generate/verify Rust and TypeScript.
- B: Rust types first with `schemars`, generate JSON Schema and TypeScript.
- C: Hand-maintain all three representations.
- Provisional direction: spike A and B; reject C unless generation proves unusable.

### D2. Event envelope

Freeze at least `event_id`, `event_type`, `event_version`, `aggregate_id`, `aggregate_version`, `expected_version`, `idempotency_key`, `project_id`, `task_id`, optional `node_id/session_id`, `actor`, `evidence_grade`, `occurred_at`, `recorded_at`, optional `commit_sha`, and typed `payload`.

### D3. Concurrency and durability

- Compare an OS/file lock adapter with a proven cross-platform lock crate.
- Define optimistic version-conflict results and retry rules.
- Define flush/fsync policy, partial-line recovery, and quarantine behavior.
- Prove behavior with two processes and crash injection on macOS and Windows.

### D4. Projection contract

Define checkpoint/version metadata, deterministic rebuild, invalid-event handling, stale/partial states, and forward-compatible unknown events.

### D5. Identity and path semantics

Define stable IDs independently from display names and native paths. Preserve Windows drive/UNC/case semantics; do not normalize different filesystem identities into one string.

## Required Spikes

1. Round-trip one read model and one event through JSON Schema, Rust, TypeScript, and fixture validation.
2. Concurrent append from two native processes with duplicate idempotency keys.
3. Kill a writer after a partial write, then rebuild and report recovery evidence.

## Deliverables

- Event envelope schema and compatibility rules.
- Domain vocabulary and aggregate ownership table.
- Append/conflict/error taxonomy.
- Projection/checkpoint/rebuild state machine.
- Cross-platform locking decision record.

## Exit Criteria

- One approach wins D1-D5 with recorded evidence and rejected alternatives.
- M0 view schemas do not import V2 workflow types.
- M2 can implement append/rebuild/idempotency without reopening identity or wire-format semantics.
- The native concurrency spike has a reproducible command and expected result.

## Not Decided Here

- MCP tool names and resource URIs: RFC-002.
- Project Intelligence invalidation: RFC-003.
- Task/PlanNode transitions: RFC-004.
- Worktree lifecycle: RFC-005.

## M0 Freeze Record

- `D1 decided`: JSON Schema 2020-12 is the canonical wire source. TypeScript
  read-model types are generated by `json-schema-to-typescript` and checked for
  drift by `npm run v3:contracts:check`.
- `D1 rejected`: hand-maintaining JSON Schema, TypeScript, and Rust in parallel.
  Rust-first generation is deferred because M0 owns no production Rust domain;
  M2 must round-trip one read model and event before adding core types.
- `D2-D5 deferred to M2`: M0 freezes only view identity, path, evidence,
  freshness, completeness, warning, error, and version semantics. Event
  envelope, locking, durability, and checkpoint implementation remain open.
- Evidence: five schemas, 12 deterministic scenarios, negative sentinels,
  generated TypeScript drift test, and the schema hashes in the M0 Task Pack.
- M0 exit status: passed for the view-contract boundary; native concurrency and
  crash spikes remain required before RFC-001 can become fully accepted.
